\section{Desarrollo del sistema}
\label{sec:des-intro}

Con base en el diseño anterior, se construyó el prototipo funcional del sistema, cuyo código fuente se encuentra publicado en el repositorio de GitHub \url{https://github.com/antoniotorresxd/ia-spice}. A continuación se describe el modelo de base de datos, el funcionamiento del catálogo de circuitos y de los valores definidos, y las pantallas que integran la aplicación web.

\subsection{Modelo entidad-relación de la base de datos}
\label{subsec:des-erd}

La base de datos en PostgreSQL se diseñó para guardar las cuentas de usuario, la configuración de los modelos de inteligencia artificial y el historial de circuitos diseñados. La tabla central corresponde al usuario, la cual se relaciona con sus sesiones activas, sus cuentas de acceso y sus conexiones registradas hacia proveedores de IA; de estas conexiones dependen las asignaciones que indican qué modelo utiliza cada agente del sistema.

Para organizar el trabajo, cada usuario puede crear varios proyectos y agrupar dentro de ellos sus conversaciones. A su vez, cada conversación concentra tres tablas principales: los mensajes intercambiados en el chat entre el usuario y el asistente, el registro de cada corrida ejecutada (donde se guardan las mediciones de las simulaciones y las decisiones del Curador) y los archivos o artefactos finales del circuito (que almacenan el código SPICE, la lista de materiales y la explicación del diseño). Adicionalmente, se cuenta con una tabla para el catálogo de circuitos base del sistema y un espacio donde el grafo de agentes guarda sus puntos de control. La relación completa entre estas entidades se muestra en la figura~\ref{fig:erd-base-datos}.

\subsection{Catálogo de circuitos, ajuste a valores definidos y modo de análisis}
\label{subsec:des-topologias}

Para el diseño de circuitos, el sistema combina el uso de un catálogo base con el diseño de bloques abiertos. El catálogo reúne diecisiete circuitos analógicos clásicos divididos en cinco familias (divisores y fuentes, filtros pasivos y redes RLC, circuitos con diodos, etapas con transistores BJT y configuraciones con amplificadores operacionales), los cuales cuentan con sus ecuaciones de diseño listas para calcular los componentes de manera directa. Cuando el usuario solicita un circuito que no forma parte del catálogo, el sistema lo trabaja como un bloque genérico en el que el modelo de lenguaje propone el circuito SPICE y lo envía al mismo ciclo de simulación en \texttt{ngspice} y revisión del Curador. Asimismo, cuando un diseño requiere conectar varias etapas en cascada —por ejemplo, un filtro seguido de un amplificador—, cada etapa se encapsula como un subcircuito y se enlaza la salida de una con la entrada de la siguiente dentro de un mismo archivo SPICE para simular el circuito completo. En la tabla~\ref{tab:catalogo-topologias} se muestran los diecisiete circuitos del catálogo.

Dado que las fórmulas de diseño entregan valores teóricos exactos que no siempre existen como piezas reales, antes de simular cada propuesta el sistema aproxima las resistencias, capacitores e inductores hacia los valores definidos más cercanos de las series estándar (E12, E24 y E96), o bien combina dos piezas en serie o en paralelo cuando se requiere mayor cercanía a la meta. Del mismo modo, asigna modelos SPICE definidos para los diodos, transistores BJT y amplificadores operacionales, integrando todos los elementos en la lista de materiales del circuito.

Por otra parte, cuando el usuario pide analizar un circuito que ya tiene valores dados en lugar de diseñar uno nuevo, el módulo de análisis plantea y resuelve las ecuaciones del circuito (por nodos, mallas, reducciones serie y paralelo o equivalente de Thévenin y Norton) para obtener los voltajes, corrientes o ganancias buscadas, comprobando el resultado contra la simulación en \texttt{ngspice} antes de entregar la explicación paso a paso.

\section{Pantallas del prototipo funcional}
\label{sec:des-pantallas}

La aplicación web se divide en cinco vistas principales que guían al usuario desde el acceso a su cuenta hasta la consulta y descarga de los circuitos diseñados.

\subsection{Pantalla de inicio de sesión y ruta de solución}
\label{subsec:des-pantalla-auth}

La pantalla de inicio de sesión permite entrar al sistema o registrar una cuenta nueva en el panel derecho, con soporte para tema claro y oscuro. En su panel izquierdo muestra de forma visual la ruta de solución por la que pasa cada solicitud (desde el Orquestador y el Cálculo hasta la Síntesis y el Curador), como se observa en la figura~\ref{fig:pantalla-login}.
