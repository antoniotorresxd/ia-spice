# Client Project and Conversation Workspace Design

Date: 2026-07-15

## Goal

Extend the authenticated client workspace with a focused new-request flow, a global project directory, project detail views, and full-screen conversations. All data remains mocked behind client service interfaces so the future Hono RPC implementation can replace the mock without redesigning components.

## Approved product model

The information hierarchy remains:

```text
Project
  Conversation
    Execution
      Generated files
```

A new request immediately creates a temporary conversation with no project. The interface never interrupts the first message by asking for a project. Users organize work afterward by dragging an unassigned conversation onto a project in the sidebar or project drop target.

Dropping a conversation onto a project updates the mock service, moves the conversation from `Sin proyecto` into the expanded project, displays a discreet success notification, and offers an undo action. A failed assignment leaves the conversation in its original location and displays a safe retry message.

## Navigation

The existing application sidebar becomes the persistent navigator for:

- Inicio
- Nueva solicitud
- Proyectos
- Conversaciones
- Archivos
- Ejecuciones
- Sin proyecto
- expandable projects and their recent conversations
- profile and settings

Projects expand independently. Their children are conversations, not executions or files. The active destination and active conversation are visibly selected and use accessible current-state semantics.

## New request

`Nueva solicitud` is a clean, focused route. The central workspace contains:

- the prompt `¿Qué quieres diseñar?`;
- one large natural-language composer;
- an optional context attachment control;
- the existing automatic agent/model behavior;
- a few compact example prompts.

Usage cards, activity summaries, project cards, and file lists do not appear on this route. Submitting valid text creates a temporary conversation through the mock service and navigates to its full-screen conversation view. Empty text remains a client-side validation error.

## Global projects view

`Proyectos` uses a dense Linear-style table rather than large cards. Each row contains:

- project name and short description;
- conversation count;
- generated-file count;
- activity or last-updated state.

The view includes search, ordering controls, and a client-only `Nuevo proyecto` flow. Creating a project requires a non-empty name, updates mock data, and opens the new project. Duplicate display names are allowed because identity comes from the project ID.

## Project detail

Selecting a project opens its landing page rather than automatically opening the latest conversation. The header presents project identity, description, and `Nueva conversación`.

The content uses two tabs:

1. `Conversaciones` is the default tab. It shows a dense list with title, prompt excerpt, state, generated-file count, and last update.
2. `Archivos` shows files generated by conversations in the project, with name, type, originating conversation, partial/complete state, and generation date.

Both tabs support local search and filters. Selecting a conversation opens the full-screen conversation route. Selecting an originating conversation from the files tab opens that same route.

## Conversation view

The selected direction is a clean, full-screen conversation inspired by Codex. The sidebar remains visible, while the central workspace is dedicated to:

- conversation title and project breadcrumb;
- execution state, token usage, and generated-file count;
- user requests and assistant/system results;
- the operational timeline already used by the home;
- generated deliverables;
- a composer for continuing the conversation.

There is no permanent master list beside the conversation. Switching conversations happens through the sidebar, project landing page, or global conversations view. Unassigned conversations show `Sin proyecto` in the breadcrumb and remain draggable from the sidebar.

## Global conversations view

`Conversaciones` provides the cross-project directory that the sidebar hierarchy cannot provide efficiently at scale. It uses a dense list with search and filters for project, execution state, and updated date. Each row includes conversation title, project or `Sin proyecto`, status, file count, and last update. Selecting a row opens the full-screen conversation view.

## Client architecture

The feature will extend `src/features/home/` rather than create a disconnected second shell. Focused route screens compose existing workspace primitives and receive data through a project/conversation service boundary.

Expected units:

```text
src/features/home/
  components/
    WorkspaceShell.tsx
    WorkspaceSidebar.tsx
    NewRequestScreen.tsx
    ProjectsScreen.tsx
    ProjectScreen.tsx
    ProjectConversationList.tsx
    ProjectFileList.tsx
    ConversationsScreen.tsx
    ConversationScreen.tsx
    ConversationDropTarget.tsx
  model/
    workspace-types.ts
    workspace-fixtures.ts
  services/
    workspace-service.ts
    mock-workspace-service.ts
```

Exact filenames may reuse or extract the existing `HomeSidebar`, `HomeScreen`, `NaturalLanguageComposer`, `ActivityTimeline`, and `ContextPanel`, but these responsibilities remain separate:

- the shell owns persistent navigation layout;
- route screens own loading and selected-route state;
- lists only render collections and emit selection/filter actions;
- drag targets only interpret drag data and emit assignment callbacks;
- services own mock persistence and deterministic mutations;
- components never import fixtures directly.

## Service boundary

The client service exposes typed operations for:

- listing and reading projects;
- creating a project;
- listing conversations globally or by project;
- reading one conversation and its executions/files;
- submitting a new request;
- continuing a conversation;
- assigning a conversation to a project;
- restoring its previous project for undo;
- listing project files.

The implementation remains client-only. The mock maintains in-memory state for the current app session. No server route, database model, authentication behavior, or Python agent code changes in this slice.

## Loading, empty, and error states

- New request always retains entered text if a mock submission fails.
- Empty project lists show one focused creation action.
- Empty project conversations show `Nueva conversación` and accept dropped unassigned conversations.
- Empty project files explain that files appear after successful executions.
- Loading states preserve the table or conversation geometry with subtle skeleton rows.
- Route load failures provide retry without navigating away.
- Drag assignment failures restore the original sidebar position.
- Long names truncate in the sidebar and wrap safely in detail headers.

## Accessibility and interaction

- Sidebar project disclosure controls expose expanded state.
- Drag and drop has a keyboard equivalent: `Mover a proyecto` in each conversation action menu.
- Drop targets announce availability and successful assignment through a polite live region.
- Tabs use semantic tab roles and keyboard navigation.
- Lists and tables preserve meaningful accessible names.
- Focus moves to the main route heading after navigation and returns to dialog triggers after dismissal.
- Status never relies on color alone.
- Reduced-motion mode removes drag and route transition animation.

## Responsive behavior

- Desktop keeps the persistent application sidebar and a single main workspace.
- Tablet collapses project metadata columns before conversation titles or primary actions.
- Mobile uses the existing sidebar drawer; project and conversation rows become stacked but remain dense.
- Full-screen conversation content stays single-column and never requires horizontal scrolling.
- Drag assignment remains available on pointer devices; the action-menu alternative is always available.

## Testing and verification

Tests cover:

- focused new-request composition and empty validation;
- creation of an unassigned temporary conversation;
- project expansion and active conversation state;
- drag assignment, failure rollback, and undo;
- keyboard project assignment alternative;
- global project search and project creation;
- project conversation/file tabs and empty states;
- global conversation filters;
- full-screen conversation rendering and continuation;
- loading and retry states;
- responsive semantic structure and accessible controls.

Completion requires the complete client test suite, ESLint, TypeScript/Vite build, and visual inspection of desktop and mobile layouts.

## Out of scope

- Hono routes or RPC implementation;
- database persistence;
- real file download or preview;
- streaming agent responses;
- real token accounting;
- cross-user collaboration or permissions;
- project sharing and deletion.
